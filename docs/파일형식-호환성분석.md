# 파일 형식별 호환성 분석

표기: **[관찰]** 이번에 시료 파일에서 직접 확인, **[규격 지식]** 공개 규격에 대한 일반 지식(이번 실행에서 규격 원문을 열어 확인하지 않음), **[미확인]**.

| 형식 | 구조 | 확보 시료 | 우리 코드 | 원본 프로그램 검증 |
|---|---|---|---|---|
| HWPX | OPC 유사 ZIP + XML | 한/글 작성 5, rhwp 변환 4 | 무손실 글자 편집 | 없음 |
| HWP 5.x | OLE2 복합 문서 | 5 + rhwp 저장본 5 | **없음**(헤더 조사 도구만) | 없음 |
| DOCX | OPC ZIP + XML | 직접 생성 4 | 무손실 글자 편집 | 없음 |
| XLSX | OPC ZIP + XML | **없음** | 없음 | 없음 |
| PPTX | OPC ZIP + XML | **없음** | 없음 | 없음 |
| PDF | 객체·교차 참조 | **없음** | 없음 | 없음 |
| DOC / XLS / PPT | OLE2 이진 형식 | **없음** | 없음 | 없음 |

## HWPX
- **구조 [관찰]**: 첫 항목 `mimetype`(STORED, `application/hwp+zip`), `version.xml`, `Contents/header.xml`(글꼴·글자 모양·문단 모양·스타일 정의), `Contents/section0.xml`(본문), `Contents/content.hpf`(OPF 목록·메타데이터), `settings.xml`, `Preview/PrvText.txt`·`PrvImage.png`, `BinData/*`, `META-INF/*`. 5개 모두 구역 1개.
- **본문 [관찰]**: 문단 `hp:p` → 런 `hp:run` → 글자 `hp:t`. 표는 `hp:tbl/hp:tr/hp:tc/hp:subList/hp:p`. 줄 배치 캐시 `hp:linesegarray`가 문단마다 있다.
- **rhwp로 저장하면** 문단 id 재번호, 개체 태그(metatag), 일부 속성, 미리보기 미갱신, 항목 순서·압축 방식 변경이 생긴다(재현 완료, `리버스엔지니어링-현황.md` §3). → **저장 경로에 쓰지 않는다.**
- **우리 방식**: 글자 요소만 위치 기반으로 바꾼다. 바이트·구조 보존은 5개 시료로 확인했다.
- **검증 공백**: 표시·기능 보존(한/글), 줄 배치 캐시 정책, 머리말·꼬리말·각주·하이퍼링크·여러 구역·탭·줄바꿈 등(시료 없음).
- **알려진 제약**: 줄바꿈·탭·문단 나누기 편집 불가, 글자 모양 편집 불가.

## HWP 5.x (바이너리)
- **구조 [관찰]**: OLE2. `FileHeader`(서명, 버전 5.0.3.4~5.1.1.0, 플래그), `DocInfo`, `BodyText/Section0`(레코드 스트림), `BinData/*`, 요약 정보. 5개 시료는 모두 **압축** 플래그만 켜짐(암호·배포용·DRM 없음).
- **편집 [미확인]**: 레코드 스트림 압축 해제·재압축, OLE 스트림 재기록, 구역 크기 갱신이 필요하다. rhwp는 HWP 저장을 지원하나 그 결과가 한/글에서 열리는지 확인하지 못했다(저장본에서 레코드 수는 같음).
- **HWPX와 별개 형식이다.** HWPX 편집이 된다고 HWP를 지원한다고 표시하지 않는다.

## DOCX
- **구조 [관찰, 직접 생성 시료]**: `[Content_Types].xml`, `word/document.xml`(본문 `w:p/w:r/w:t`), `word/header*.xml`, `footer*.xml`, `styles.xml` 등.
- **우리 방식**: `w:t` 글자만 바꾼다. 앞뒤 공백이 있으면 `xml:space="preserve"`를 붙인다. 서식 요소(`w:rPr`)는 그대로다. python-docx가 편집본을 읽어 표 셀·머리글·바닥글 글자를 확인했다.
- **알려진 제약**: 텍스트 상자는 `mc:AlternateContent`에 선택(Choice)과 대체(Fallback)가 같은 글자를 따로 담는다. **선택 쪽만 고치면 대체 쪽 글자는 그대로**라서 대체 내용을 그리는 프로그램에서 옛 글자가 보일 수 있다(시험으로 확인, 해소 방법은 미정). 각주·미주 편집은 시료가 없어 시험하지 못했다.
- **Word 2024(16.0.17932) 실측 (2026-10-22, `tools/verify-word.ps1`, 읽기 전용 자동화로 Word가 읽은 값을 JSON으로 받음)**: 편집본 6개가 모두 열렸고 Word가 읽은 문단·표 셀·머리글·바닥글·글상자 글자가 기대와 같았다(`verify-out/word-results.json`). 예: basic 편집본의 문단 3개 교체(특수문자·이모지·앞뒤 공백 포함)가 그대로 읽힘, table 편집본은 셀 4개 중 1개만 바뀜, headerfooter 편집본의 머리글·바닥글 교체, textbox 편집본의 글상자 글자 `EDIT 상자`(Word는 선택(Choice) 쪽을 읽음). 모두 1쪽, 호환 모드 14.
- **시료 결함 발견**: 처음 만든 글상자 시료(손으로 쓴 `mc:AlternateContent`)는 **Word가 열지 못했다**(원본 시료 자체가 오류 파일). 파이썬 `python-docx`는 같은 파일을 문제없이 읽었으므로 **python-docx 교차 검증만으로는 Word 호환을 보장하지 못한다.** Word 2010 이후 구조(앵커 도형 + `wps:txbx`, VML Fallback)로 시료를 다시 만들자 원본과 편집본 모두 열렸다.
- **검증 공백**: **Word가 만든 실제 문서**(Word로 새 문서를 저장하려 하자 자동화가 멈췄고, 저장 대화상자 때문으로 추정하나 확인하지 못함), 화면 표시·인쇄 비교, **Word가 만든 실제 문서**(구조가 python-docx와 다를 수 있음: 분할된 런, 필드, 변경 추적, 책갈피 등).

## XLSX (설계 메모, 코드 없음)
- **[규격 지식]** `xl/workbook.xml`(시트 목록, `r:id`), `xl/_rels/workbook.xml.rels`, `xl/worksheets/sheetN.xml`(`<c r="A1" t="..." s="..">` 셀), `xl/sharedStrings.xml`, `xl/styles.xml`(숫자·날짜 서식). 셀 유형 `t`: 생략(숫자), `s`(공유 문자열 번호), `str`(수식 문자열 결과), `inlineStr`, `b`, `e`, `d`.
- **구현 시 위험(가설)**: 숫자 셀을 문자열로 바꾸는 것(이전 시험에서 `poi-unicode.xlsx` A1이 이렇게 바뀌었다고 기록됨), 공유 문자열을 여러 셀이 공유하므로 항목을 직접 고치면 다른 셀이 바뀜, 수식 셀의 캐시 값 갱신, 날짜 서식 숫자, `calcChain`, 병합 셀.
- **현재 시료가 없어 가설을 검증할 수 없다.** E8(Excel에서 한 요소씩 만든 시료)이 선행 조건이다.

## PPTX (구현됨, 2026-10-22)
- **구조 [관찰, python-pptx 생성 시료]**: `ppt/presentation.xml`의 `p:sldIdLst`와 관계 파일로 슬라이드 순서를 얻고, 슬라이드의 관계에서 `notesSlide`를 찾는다. 글자는 `a:p/a:r/a:t`, 표 셀은 `a:tc`, 슬라이드 번호 등은 `a:fld`.
- **우리 방식**: `a:t`만 위치 기반으로 바꾼다. **필드(`a:fld`) 글자는 고치지 않는다**(프로그램이 채우는 값). 레이아웃·마스터·도형·애니메이션은 그대로.
- **PowerPoint 2024 실측**: `tools/verify-powerpoint.ps1`(읽기 전용, 창 없이)로 원본과 편집본 모두 열렸고, 제목·본문(여러 글자 모양 문단)·표 셀·텍스트 상자·발표자 노트가 기대한 값으로 읽혔다(`verify-out/powerpoint-results.json`). 슬라이드 번호 필드는 그대로.
- **검증 공백**: PowerPoint가 만든 실제 파일(레이아웃·그룹 도형·SmartArt·슬라이드 쇼), 화면·인쇄 비교, 애니메이션.

## PDF (구현됨, 2026-10-22)
- **구조 [관찰]**: 직접 만든 시료에서 xref 표, xref 스트림 + 객체 스트림 두 방식을 모두 읽는다. 쪽 트리(`Pages/Kids`)와 상속되는 `MediaBox`를 해석한다.
- **우리 방식**: **증분 갱신**으로 `/Text` 주석만 덧붙임(자세한 내용 `PDF-구현결과.md`).
- **검증 공백**: Acrobat Reader 표시, 실제 Office·Acrobat이 만든 PDF.

## DOC / XLS / PPT
- OLE2 이진 형식. 시료도 코드도 없다. 계획: 별도 평가.

- PDF **[규격 지식]**: 객체와 교차 참조 표, **증분 갱신**으로 주석을 덧붙이는 방식이 원본 보존에 유리. 시료 없음. 뷰어는 이 PC에 Acrobat Reader가 있다.
- DOC/XLS/PPT: OLE2 안의 이진 스트림이며 형식별 해석이 별도로 필요하다. OOXML과 **따로 평가**해야 하고 지금은 시료도 코드도 없다.
