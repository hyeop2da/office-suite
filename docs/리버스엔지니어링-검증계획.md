# 리버스엔지니어링·호환성 검증 계획

원칙: 한 번에 한 요소만 바꾼다. 관찰(사실)과 가설을 분리한다. 비교 도구는 `tools/compare.ts`(구조), `tools/inventory.ts`(기능 목록), `tools/hwp_inspect.py`(HWP 헤더)이며 모두 이미 구현·시험되어 있다.

## 사전 조건과 안전 규칙

이 PC에는 한컴오피스 2022와 Office 2024가 있으나 **Word, Excel, 한/글이 사용자 문서를 연 채 실행 중**이다. COM 자동화는 실행 중인 같은 인스턴스를 공유하므로:

1. 사용자가 해당 프로그램을 **저장하고 닫거나**, 열린 문서를 건드리지 않고 시험 문서만 읽기 전용으로 열고 닫는 것을 **명시적으로 허락**해야 시작한다.
2. 시험 문서는 복사본(`verify-out/`)만 쓴다. 인스턴스를 종료(`Quit`)하지 않는다. 대화 상자가 뜨면 중단한다.
3. 한/글 COM의 파일 접근 보안 모듈 등록(레지스트리 수정)은 **하지 않는다**(보안 설정 변경). 대화 상자 없이 안 되면 한/글 창에서 직접 열고 화면 확인으로 대체한다.

## 성공 기준의 3분리

각 실험 결과를 **바이트 보존 / 구조 보존 / 표시·기능 보존** 중 어디에 해당하는지 표시한다. E1~E3, E6, E7은 세 번째(표시·기능)를 처음으로 채운다.

## 코드 역분석이 필요한가

E1~E10은 모두 외부 동작 관찰과 파일 비교로 수행한다. 코드 역분석을 검토하려면 먼저 (1) 이 실험들로 풀리지 않는 **구체적 문제**가 확인되어야 하고 (2) `법적-보안-검토.md`의 조건을 법률 자문으로 확인해야 한다. 현재 그런 문제는 없다.
