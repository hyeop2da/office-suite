# XLSX 구현 결과 (2026-10-22)

코드: `src/xlsx.ts`(코어), `src/sheet-session.ts`(세션), `src/app/sheet-view.ts`(격자 화면). 시험: `test/xlsx.test.ts`(21개), `e2e/app.spec.ts`의 "XLSX 흐름"(4개 시나리오 × 4 프로필). 시료: `fixtures/xlsx/`(직접 생성), 생성기 `tools/make_xlsx_fixtures.py`.

## 할 수 있는 것
시트 목록(숨김 시트 표시), 칸 읽기(숫자·글자·논리값·수식·오류·빈 칸, 서식 섞인 글자 표시, 날짜 서식 숫자의 ISO 표시), 칸 값 편집, 저장 후 재열기 검증, 되돌리기, 임시 보존, 모바일 격자 화면.

## 설계 규칙과 근거
| 규칙 | 이유 |
|---|---|
| **원래 칸의 종류를 지킨다**: 숫자 칸은 숫자만 받고(글자 입력은 거부), 글자 칸은 글자로 남는다. 빈 칸은 숫자처럼 보이면 숫자로 넣는다 | 이전 시험 기록에서 숫자 칸이 문자열로 바뀐 사례가 있었다. 요구사항 "숫자 셀 유지" |
| 숫자는 입력한 표기를 그대로 쓴다(`1.5e-07`도 유지) | 값이 같아도 표기가 바뀌는 것을 피함 |
| 바꾼 `<c>` 요소만 다시 쓴다. `sharedStrings.xml`, `styles.xml`, 다른 시트는 **바이트 그대로** | 공유 문자열은 여러 칸이 공유하므로 항목을 고치면 다른 칸이 바뀐다. 시험으로 확인 |
| 글자 편집은 `inlineStr`로 쓴다(공유 표를 건드리지 않음) | 위와 같음. Excel도 읽을 수 있는 정상 형식 |
| 칸의 `s`(서식), 기타 속성은 유지, `t`만 바꾼다 | 서식 보존 |
| 수식 칸은 편집 거부. 수식이 있는 통합문서는 편집하면 `fullCalcOnLoad="1"`을 넣어 열 때 다시 계산하게 한다 | 수식 칸의 저장된 결과 값은 편집 전 값이라 낡는다. 앱이 직접 계산하지는 않는다 |
| 새 칸·새 행은 순서에 맞게 끼우고 `dimension`, 행 `spans`를 넓힌다 | 스키마 순서 |
| 날짜 서식 칸은 `YYYY-MM-DD`를 일련번호로 바꿔 숫자로 저장(1900/1904 체계 구분) | 날짜도 숫자로 유지 |

## 검증 수준 (엄격하게)
- **통과(자동)**: 무수정 저장은 파일 전체 바이트 동일. 편집 시 바뀐 시트 XML 외 모든 항목이 바이트 동일. 파이썬 `openpyxl`이 편집본을 읽어 값·파이썬 형(`int`/`float`/`bool`/`str`)·서식·수식·시트 이름과 숨김 상태를 확인. 잘못된 입력(주소, 시트 번호, 제어 문자, 32,767자 초과, 숫자 칸에 글자)은 문서를 바꾸지 않고 거부. 브라우저에서 열기→편집→저장→내려받은 파일을 Node 코어로 재검증.
- **미검증: Excel**. 이 PC에서 Excel이 사용자 통합문서를 연 채 실행 중이라 자동화로 건드리지 않았다. **Word에서 파이썬 라이브러리가 통과시킨 시료를 Word가 열지 못한 전례가 있으므로**(`파일형식-호환성분석.md`), Excel에서 열려야 호환이라고 말할 수 있다.
- **시료의 한계**: Excel이 만든 파일이 아니다. 이 환경의 openpyxl은 문자열을 `inlineStr`로 써서, Excel식 공유 문자열 시료는 생성기가 변환해 만들었다(`types.xlsx`). 병합 셀, 조건부 서식, 표(Table), 차트, 이름 정의, 외부 링크, 피벗, 접두사가 붙은 XML(`x:sheetData`)은 시험하지 않았고, 접두사 XML은 명시적으로 거부한다.

## 알려진 제약
수식 편집과 재계산 없음 · 서식이 섞인 글자는 편집하면 서식이 사라짐(화면에 경고) · 병합 셀의 숨은 칸을 편집할 수 있음 · 행·열 삽입·삭제, 서식 변경, 새 시트 없음 · 큰 시트는 50행씩 표시(열은 최대 40개) · 저장 후 검증은 20만 칸까지 전체 비교, 넘으면 수정한 칸만 확인.
