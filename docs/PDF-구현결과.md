# PDF 구현 결과 (2026-10-22)

코드: `src/pdf.ts`(구조 읽기·증분 갱신), `src/pdf-session.ts`, `src/app/pdf-view.ts`(pdf.js 화면). 시험: `test/pdf.test.ts`(14개), `e2e`의 "PDF 흐름"(4개 시나리오 × 4 프로필) + 가짜 PDF 거부. 시료: `fixtures/pdf/`(직접 생성, `tools/make_pdf_fixtures.py`).

## 할 수 있는 것
열람(pdf.js 4.10.38, Apache-2.0, **PDF를 열 때만** 내려받음), 쪽 이동·쪽 번호 입력, 확대·축소·맞춤, **텍스트 메모 추가**(메모 모드에서 쪽을 눌러 위치 지정), 기존 `/Text` 메모 표시, 새 메모 지우기, 저장 후 재열기 검증, 임시 보존.

## 저장 방식: 증분 갱신 (원본 보존)
새 주석 객체, 바뀐 쪽(또는 `Annots` 배열) 객체, 새 xref 구간과 트레일러를 **원본 뒤에 덧붙인다.** 원본 바이트는 앞부분에 그대로 남는다(시험으로 확인: 저장본의 앞 N바이트 == 원본). xref 표 PDF는 표로, xref 스트림 PDF는 비압축 xref 스트림으로 갱신한다. 객체 스트림 안에 있던 쪽 객체는 번호를 유지한 채 새 판을 비압축으로 덧붙인다.
메모는 `/Text` 주석(노트 아이콘, `Contents`는 UTF-16BE, 선택적 `T`=작성자)이다. 이미 `/Annots`가 있으면(직접 배열이든 간접 배열이든) 기존 주석 뒤에 붙인다.

## 검증 수준
- **통과(자동)**: 3종 시료(xref 표, 기존 링크 주석이 있는 쪽, **객체 스트림 + xref 스트림**)에서 쪽 수·쪽 크기 읽기, 메모 추가, 원본 바이트 보존, **파이썬 `pypdf`(strict)** 가 쪽 수·주석·쪽 글자를 확인, **pdf.js(독립 뷰어 엔진)** 가 메모를 주석으로 인식하고 쪽을 엶, 두 번 연속 갱신(`Prev` 연결). 브라우저에서 그려진 캔버스에 글자 픽셀이 있음, 메모 추가→저장→재검증, 메모를 지우면 원본과 바이트 동일, 임시 보존 복구.
- **버그를 시험이 찾음**: PDF의 Flate 스트림은 zlib 형식인데 처음에 ZIP용 raw deflate로 풀어 객체 스트림 PDF를 읽지 못했다. 수정함.
- **미검증: Adobe Acrobat Reader**. 이 PC에 Reader 26.002가 있지만 화면 제어 권한을 받지 못해 열어 보지 않았다. 메모 아이콘이 Reader에서 어떻게 보이는지(외형 스트림 `/AP` 없이 주석만 있음)는 미확인이다.
- **시료의 한계**: Word·PowerPoint로 PDF를 내보내 보았으나 이 PC의 Fasoo DRM이 내보낸 PDF도 암호화해(`DRMONE` 머리글) 쓸 수 없었다. 실제 Office·Acrobat이 만든 PDF(폰트 서브셋, 태그, 양식 필드, 선형화)로는 시험하지 못했다.

## 알려진 제약
암호화된 PDF 거부 · Flate 이외 스트림 필터(LZW, ASCII85 등)로 된 xref/객체 스트림 거부 · 서명된 PDF는 증분 갱신이 서명 범위를 바꾸지 않지만 서명 유효성 표시는 확인하지 못함 · 글자 선택·검색·양식 채우기·펜 필기·도장 없음 · 메모 아이콘 외형 스트림 없음(뷰어가 기본 아이콘을 그림) · 매우 큰 PDF는 메모리에 통째로 올림(앱 100MB 상한) · 회전된 쪽은 메모 위치를 pdf.js 변환으로 계산하나 회전 PDF 시료로 시험하지 않음.
